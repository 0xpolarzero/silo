Silo Help

Silo runs Linux development sandboxes on macOS and Linux. Your sandbox disks remain separate from the application.

Sandboxes

Use Add above the sandbox list to create a VM and choose its name and resources. Start, stop, or restart a sandbox from its row. Open its terminal or editor from the sandbox controls. CPU and memory edits stop a running sandbox and apply on its next start. Existing sandbox names and disk sizes cannot change.

Storage

Choose Storage from a local sandbox’s menu to compare disk space allocated on your computer with space used inside its workspace. Deleted files can leave unused space allocated in the disk image. Reclaim unused space releases that space without deleting files; start the sandbox first. Reclamation applies to the workspace disk, not the runtime disk. If Silo asks you to restart the sandbox, restart it before reclaiming so it uses the corrected storage runtime.

Silo also reclaims automatically after seven days since the last success, and before a normal stop when the last success was at least 24 hours ago. A sandbox with no previous successful reclaim is eligible on its next start. Failed automatic attempts wait at least 24 hours before retrying. Quit gives reclamation a shared 15-second command budget across local sandboxes; a failed reclaim does not prevent normal shutdown.

Files browses sandbox directories. Logs shows runtime output, Activity shows operations and their results, and Network manages exposed ports. Select the sandboxes you want to inspect in these views.

Linux desktop

Select Linux desktop when creating a sandbox, or choose Add desktop in an existing sandbox's configuration. Installation adds Xfce to the same Ubuntu sandbox; files and terminal tools stay in place. Desktop packages remain installed.

Start desktop with sandbox is on by default. Turn it off to start the desktop explicitly from its viewer. Changing this setting to off leaves an existing session running. Stopping the VM always stops its desktop. An explicit desktop stop lasts until you start it again or the VM next starts with automatic startup enabled.

Open desktop opens an interactive view. Closing the view leaves applications running. Stopping or restarting the desktop closes graphical applications, so save your work first. Independent terminal jobs continue. Install additional Linux applications from the desktop terminal; its user has passwordless sudo.

Adding a Linux desktop also installs Luda tools and its skill for supported agents, including agents installed later. Use Set up agent tools or Repair agent tools in an existing desktop viewer, then reconnect your agent. Silo does not install or authenticate agents or coordinate their input. Guest applications can access display :1 as silo. Older VMs require migration or recreation before working access. VMs share one account across terminals, SSH, editors, and desktop apps; use sudo for administration. An SSH project does not automatically redirect a host-specific computer-use plugin into the sandbox.

Logs and history

Search in Logs searches all retained history for the selected sandboxes, including stopped sandboxes. Add source or date filters to narrow the search, remove their chips or use Clear to reset them, Load older to browse more records, and the surrounding-logs action to read the context of a match. Follow refreshes recent output; Pause lets you inspect it.

Silo keeps logs for at most seven days, with a shared 250 MiB limit per sandbox. Oldest segments are removed first; records in a segment can expire up to a day early. The displayed history boundary tells you what is still available. Computer connection errors and expired history are reported separately from log messages.

Copy copies the fetched records with their timestamps and identities. Export… saves all matching records, including pages you have not loaded, as a JSON Lines file. You can cancel an export; an incomplete export does not replace an existing file. Exported files remain yours until you delete them. Review logs for private information before sharing them.

Remote computers

On the owning computer, enable SSH access (Remote Login on macOS), then enable Settings → Computers → Allow remote management. On your computer, choose Connect computer… and paste the displayed address. Both computers need Silo 0.2.0 or newer. Keep Silo running on the owning computer. Accounts, secrets, and backups remain managed on that computer.

GitHub and secrets

Connect your account in GitHub, then choose repository access for each sandbox. Configure the Git author separately. Use Secrets to manage sandbox secrets. Check the displayed operation result; if a change requires a restart, Silo tells you.

Backup and restore

On the Backup page, use Create backup… to select sandboxes and a destination, then review and confirm. Use Choose backup… under Restore backup to choose an archive. Silo verifies it before asking you to confirm the sandbox name and restore. Watch progress and the final result on the Backup page.

Menus

On Linux, click Menu in the window toolbar, tap Alt, or press F10 to reveal the application menu. Use the arrow keys to navigate. Press Escape to dismiss it and return to your previous control. On macOS, use the menu bar at the top of the screen.

Settings and updates

Open Silo → Settings… with ⌘, on macOS. Configure startup behavior, preferred applications, notifications and appearance there.

Silo checks for updates shortly after launch and daily while open. Failed checks retry automatically. You can turn automatic checks off in Settings.

Silo → Check for Updates… opens Updates and checks for a release. You choose when to download and install. Save your work before confirming an update that stops running sandboxes. Silo restarts those sandboxes after updating. A failed check does not mean your version is up to date.

Linux AppImage installations support in-app updates. For Debian installations enrolled in Silo’s software source, quit Silo and use Software Updater. For a manual installation, choose View installers on GitHub, open Assets, and download the installer for your system.

Navigation

Use Search or Jump To… (⌘K on macOS, Ctrl K on Linux) to find pages, available sandbox actions, and update actions. Search for update to check for a release, download an available update, or restart and install a verified update. Running sandboxes still require confirmation before installation. For manual installations, the command opens the installer release page. The Go menu provides direct navigation. Closing the main window leaves Silo running when a status icon is available; otherwise it quits. Quit stops Silo’s local VMs and preserves their disks. VMs on other computers keep running. A shutdown failure keeps Silo open with an error.

Help with a problem

Read the operation's error and expandable details first. Check Logs and Activity for the affected sandbox. When reporting a problem, include your Silo version, operating system and steps to reproduce it. Remove credentials and private information before sharing logs.
