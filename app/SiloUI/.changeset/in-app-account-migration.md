Sandboxes that still use the old account layout now offer **Migrate to the silo account** on their page and in their ⋯ menu, instead of an error that only pointed to a command-line script. Before anything changes, Silo shows the steps, the size and location of the backup, and whether there is enough free space, and warns that files inside the sandbox are rewritten. On Linux, it also warns when the computer has less memory available than the sandbox can use, because the computer may stop the sandbox midway if it runs out. The migration waits its turn in the operation queue and shows its current step there; it can be cancelled while the disks are being backed up, which leaves the sandbox unchanged and stopped. When it finishes, the sandbox is stopped and ready to start, and the backup is kept. If it fails, the sandbox shows the exact error with Details and the backup location, and Retry continues with the same backup; a sandbox that stopped unexpectedly is reported as such, with a hint to free memory. A sandbox on another computer is migrated by that computer, which must also run this version. The command-line migration script was removed; it no longer worked with current sandbox storage.
