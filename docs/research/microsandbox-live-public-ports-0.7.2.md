# MicroSandbox 0.7.2 live public ports

Silo's Network panel sends `ports_list`, `port_add`, `port_remove`, and `port_probe` to the per-VM host control socket. It expects a `ports` array with `guest_port`, `host_port`, and `host_bind: "127.0.0.1"`; `host_port: 0` asks the runtime to choose an available port. `port_probe` expects `ok: true` and a `reachable` boolean from a direct guest TCP handshake. Source: `app/SiloUI/src-tauri/src/network.rs` (`control`, `observe`, and `desktop_port`).

The pinned MicroSandbox 0.7.2 host control decoder did not define those operations. Source: `crates/runtime/lib/client/control.rs` in the pinned native source. Its `PortPublisher` created host listeners only from startup `NetworkConfig.ports`, and its TCP listener called `NetworkPolicy::evaluate_ingress` before queueing a connection to smoltcp. Source: `crates/network/lib/engine/ports/publisher.rs`. The multi-tenant network profile cleared startup publications. Source: `crates/network/lib/engine/network.rs` (`enforce_deployment_profile`).

The upstream patch adds a bounded host-loopback TCP control path through the existing runtime executor and network poll thread. The poll thread binds before `port_add` returns and reports the bound port. It owns listener and relay tasks. `port_remove` cancels the listener and accepted relays before acknowledgement, releases the listening port, and rejects queued connections from the removed mapping. Publisher drop aborts its live tasks. A probe also evaluates ingress policy and attempts a direct TCP handshake through smoltcp without opening a host listener. At most 16 handshakes are pending, each with a 500 ms deadline and 800 ms response wait. The existing listener loop still evaluates ingress policy on every accepted connection. `SmoltcpNetwork` does not expose the live control handle for multi-tenant deployments. The JSON and framed control transports use the same executor operation.

The Silo Network panel stores only guest TCP port, optional host TCP port, and an HTTP/HTTPS scheme hint. It has no UDP or non-loopback bind setting. Native startup `NetworkConfig.ports` remains a separate mechanism; the new live list reports the live loopback mappings controlled by these operations. Source: `app/SiloUI/src-tauri/src/network.rs` (`Mapping`, `validate`, and `control`).

The source-compatible reference is the authenticated Silo-patched MicroSandbox 0.6.17 source at `predecessor-0.6.17/source/crates/network/lib/ports/publisher.rs` on the task devbox: `PortsHandle::probe` checks ingress and uses a direct smoltcp socket; `LiveMapping` cancellation stops queued and accepted host relays. The 0.7.2 adaptation retains poll-thread listener ownership.
