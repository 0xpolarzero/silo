# E2B PoC access and viewer source audit

Date: 2026-09-23  
Scope: read-only audit of `experiments/e2b-local/{tcp-bridge.py,ssh-proxy.py,server.py,index.html,viewer-harness.swift}`, adjacent PoC tests, and existing Silo editor/network/viewer contracts. No tests, UI automation, runtime commands, or service/VM mutations were run.

## Findings

### TCP relay half-close behavior

**Source finding:** `tcp-bridge.py` defines a framed stream where `0x00 || bytes` carries data and `0x01` closes one sending half. Its inbound task forwards `0x01` to the guest socket with `writer.write_eof()` and continues reading the WebSocket; its outbound task sends `0x01` only after the guest socket read side reaches EOF ([tcp-bridge.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/tcp-bridge.py:10)). The server waits for `FIRST_COMPLETED`, then cancels the other task ([tcp-bridge.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/tcp-bridge.py:31)). In the normal framed protocol, inbound EOF alone does not finish the inbound task, so that line by itself does not prove that the guest's final output is dropped.

**Concrete unqualified failure case:** `ssh-proxy.py` returns as soon as it receives the reverse-direction `0x01` frame, then cancels its stdin-to-WebSocket sender in `finally` ([ssh-proxy.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/ssh-proxy.py:21)). TCP permits the guest/server to close its write half while continuing to read the client half. With a peer that sends a short response, calls `shutdown(SHUT_WR)`, then waits for a final client request, the bridge emits `0x01`; the proxy exits and drops the still-open or buffered client-to-guest bytes. That violates a generic TCP half-close contract. The experiment documents this service as SSH-only, so the scenario is a real gap for any proposed reuse as a generic TCP publisher; it is not evidence that current SSH sessions fail this way.

**Separate cancellation/buffering boundary:** `tcp-bridge.py` also cancels its opposite task on first completion. A guest-side EOF task has already read and sent all available guest bytes before it completes; a client-side WebSocket disconnect removes the receiver, so dropping further output is expected. A targeted regression is still required for asymmetric FIN, slow readers, and disconnects during large transfers because these task lifetimes are where future changes could silently discard data. Do not describe the bridge's current `FIRST_COMPLETED` as a reproduced data-loss bug without the fixture result.

**Bounds:** the guest WebSocket server sets `max_size=1 MiB`, but `ssh-proxy.py` connects with `max_size=None`. Current bridge output is chunked at 64 KiB and input frames from the proxy are bounded by the server's configured WebSocket limit, but the receiving client has no explicit frame-size guard of its own ([tcp-bridge.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/tcp-bridge.py:27), [ssh-proxy.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/ssh-proxy.py:10)). `os.write` correctly loops on partial writes but is dispatched with `asyncio.to_thread`; a blocked pipe write can outlive coroutine cancellation. Test slow-reader backpressure and process/socket cleanup rather than assuming `max_size=None` alone causes a current memory exploit.

**Existing test evidence:** `qualification.py::ssh_test` sends 2 MiB plus Unicode through SSH, sends stdin EOF and requires a remote SHA-256 response, checks SFTP bytes, exit status/stderr, active key revocation, and distinct host keys ([qualification.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/qualification.py:228)). The handoff and README report those historical live results, but those are not a fresh run in this audit. The current test covers client-to-guest EOF followed by guest output. It does not cover guest-to-client EOF followed by continued client input, slow readers, malformed frames, large-transfer disconnects, or generic TCP. There is no dedicated bridge unit test among `experiments/e2b-local/test_*.py`.

### Viewer asset and control API origin

**Source finding:** the page loads `vnc.html` and its noVNC assets from `/viewer/{sid}/...` in a same-origin iframe ([index.html](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/index.html:18)). The gateway fetches that path from a fixed guest-side `127.0.0.1:3002` and returns the guest response body as the page response ([server.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/server.py:192)). The same origin hosts mutating `/api/...` routes. Middleware checks request Origin against Host and asks non-GET requests to include `X-Poc-Request: 1`; it does not authenticate that header or distinguish the trusted top-level page from guest-provided viewer JavaScript ([server.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/server.py:33)). The trusted index itself sets this public header for API calls ([index.html](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/index.html:15)).

**Trust conclusion:** this is a source-supported same-origin trust-boundary defect in the PoC design, not yet an executed exploit. If guest-controlled `vnc.html` or a loaded script is altered, its JavaScript runs under the gateway origin. It can send same-origin requests with `X-Poc-Request: 1` to the gateway's unauthenticated mutation routes, including actions for a different logical desktop if its ID is known or discoverable via `/api/state`. A minimal impact proof is to have a benign replacement asset POST `/api/desktops/{other}/mode` with the required header and independently assert that the other fixture desktop's mode changes. A stronger owned-fixture proof can attempt a reversible agent action and observe the mocked guest-side call. Do not test against any user workspace.

The existing `test_cross_origin_and_simple_posts_are_rejected` proves that a POST without the custom header and a cross-origin POST are rejected; it also proves that a same-origin POST with the header is accepted ([test_controls.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/test_controls.py:69)). It does **not** exercise a guest-served asset or prove that it can issue that request. The attack is a concrete inference from the same-origin iframe, guest-response proxy, public header, and mutation routes, not a runtime observation.

`server.py` disables FastAPI docs, sets `no-store`, `nosniff`, and `no-referrer`, and fixes the proxied viewer upstream host and port. Those controls do not isolate same-origin script authority. The code comment says the fixed upstream prevents arbitrary host/port routing; source inspection does not establish path traversal or a host escape. The requested service-worker and path tests remain separate qualification cases. No service-worker behavior was exercised.

**Minimal effective direction if the exploit is reproduced:** serve trusted viewer assets from the host or a separate origin with no control API; give the viewer a short-lived, workspace-scoped transport session; keep control mutations behind an independently authenticated owner channel. A custom request header, Origin check, or hidden URL is not a substitute for separating guest script origin from control authority. No E2B master/team key is present in the browser path in the inspected code: `route()` adds the sandbox ID, port, and traffic token only to host-to-guest viewer proxy requests ([server.py](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/server.py:160)).

### Native viewer and Tauri IPC boundary

`viewer-harness.swift` creates a plain AppKit `WKWebView` and loads the supplied URL; it registers no Tauri IPC or Silo commands ([viewer-harness.swift](/Users/polarzero/code/projects/microsandbox-workspaces/experiments/e2b-local/viewer-harness.swift:1)). The historical evidence in the handoff says it rendered the desktop and saved a file using noVNC's on-screen Control button; direct automated Control chords and physical keyboard mapping remain unqualified. That is historical execution evidence, not a test run in this audit.

Current Silo source has an explicit privilege separation: `desktop-viewer.json` grants commands only to `desktop-shell-*` webviews and describes guest child webviews as capability-free. `desktop_viewer.rs` creates the nested guest webview with an origin-scoped navigation allowlist, private loopback proxy, incognito mode, and an HttpOnly cookie; `desktop_proxy.rs` injects the guest Basic credentials on the trusted local proxy side. This is evidence of intended architecture, not a proof that packaged macOS and Linux webviews enforce it under malicious content. The PoC harness's no-IPC result cannot qualify Tauri IPC isolation; use a minimal Tauri harness with the intended capability manifest and attempt IPC from guest-controlled viewer JavaScript.

## Minimal fixtures and next tests

1. **Half-close regression:** use a disposable asyncio TCP peer that sends `reply-prefix`, calls `shutdown(SHUT_WR)`, then waits for a request terminator before sending a final marker. Drive it through `tcp-bridge.py` plus the same client behavior as `ssh-proxy.py`. Assert the client receives both markers and the peer receives the request after its first FIN. This should fail while the client exits at its first `0x01` frame. Keep the existing client-EOF/final-response case as a positive control. Add a slow-output reader, client disconnect during a multi-megabyte transfer, malformed/duplicate EOF frames, and assert relay subprocess/socket cleanup and bounded buffering.
2. **Guest asset control test:** with two fake logical desktops and a fake guest viewer asset endpoint, return a harmless script from `vnc.html` that POSTs a reversible action for the second desktop with `X-Poc-Request: 1`. Load it in an isolated browser fixture and independently verify the second desktop changed. Record the existing cross-origin/simple-POST tests as controls. This turns the source inference into a reproducible exploit test without E2B credentials or a live guest.
3. **Viewer boundary matrix:** in an owned fixture, try viewer URL reuse after detach/reconnect, asset-path traversal within the fixed guest upstream, service-worker registration/persistence, and attempts to invoke privileged Tauri IPC from the viewer. Use distinct expected results: workspace-scoped viewer access only, no control API authority for guest JavaScript, and no guest-child Tauri capabilities. Repeat against the intended Tauri configuration; the standalone Swift harness cannot answer IPC questions.
4. **Silo workflow qualification:** keep SDK PTY/files distinct from SSH/editor tests. For editors verify independently saved guest bytes after Unicode edit, integrated terminal, needed dev-server forwarding, disconnect/reconnect, lifecycle rebind, and denied stale identity. For networking test protocols separately, plus revoke/remove with an established connection and a positive connection before/after the change.
