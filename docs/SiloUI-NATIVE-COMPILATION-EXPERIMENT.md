## Dependency-cache probe: not enabled in production

The experimental Python wrapper in `app/SiloUI/scripts/experiments/` uses pinned
sccache 0.12.0 and admits only the reviewed registry package `itoa` 1.0.18 library.
Application crates, build scripts, other dependencies, unknown inputs, missing
cache setup and version mismatches invoke rustc directly. The cache subprocess
receives an environment allowlist without GitHub, signing or remote-cache
variables. Each mode uses a separate daemon socket; consumers default to local
`READ_ONLY`. No workflow invokes this wrapper or uploads its output.

Three boundary tests pass, covering application bypass with rotated synthetic
configuration, package/target admission and the credential-free readonly child
environment. Run them with:

```sh
python3 -m unittest discover -s app/SiloUI/scripts/experiments -p 'test_*.py'
```

A real isolated sccache probe compiled public `itoa` with `opt-level=3`, deleting
its output between calls. The first cache miss took 0.308 s, the warm hit 0.194 s
and a new readonly daemon hit 0.194 s; the object occupied 71 KiB. sccache reported
0.080 s in the compiler on the miss. A readonly `opt-level=2` miss and a deliberately
corrupted object both compiled successfully, and cache file hashes remained
unchanged. sccache counts prevented readonly writes as write errors; this did
not fail compilation. The sandbox initially prevented the daemon socket, and
the wrapper's direct compiler fallback succeeded; the real cache checks then
ran with explicit sandbox escalation and stopped their own daemons gracefully.

This proves a narrow cache boundary and fallback, not a release improvement.
Per-invocation Python/version-check and daemon startup costs already exceed this
tiny dependency's compiler time. Do not enable the wrapper in production from
these results. A full reviewed dependency set, exact Tauri CLI test/release
feature parity, application sentinel rebuilds under Cargo, transfer costs,
Linux runs, package checks and the proposed 30% combined-compilation acceptance
gate remain unmeasured. Stop at this bounded prototype until those measurements
are funded; retain ordinary cold compilation as the production path.

Primary references: [pinned Rust cache caveats](https://github.com/mozilla/sccache/blob/v0.12.0/docs/Rust.md),
[pinned local readonly configuration](https://github.com/mozilla/sccache/blob/v0.12.0/docs/Configuration.md),
and [isolated daemon socket selection](https://github.com/mozilla/sccache/blob/v0.12.0/src/commands.rs).

## Combined implementation verification

After the shared runtime manifest and frontend experiments were complete,
the optimization checkout ran the entire native suite with the same synthetic
GitHub variables and existing Cargo target above:

```sh
cargo test --manifest-path app/SiloUI/src-tauri/Cargo.toml --locked --timings -- --test-threads=1
cargo test --manifest-path app/SiloUI/src-tauri/Cargo.toml --locked -p tauri-plugin-updater --lib -- --test-threads=1
```

The app suite passed 352 tests with 10 existing ignored tests in 12.17 s;
all ten dependency/provenance tests and all six relocated tests passed. The
updater suite passed eight tests with one existing ignored test in 0.09 s.
No ignored live test was enabled. Compilation took 17.93 s on the first combined
build, 2.05 s on the permitted rerun and 2.07 s for the updater harness.

The first sandboxed application run passed 348 tests and failed four solely
because the sandbox prohibited their local TCP/Unix listener binds. Its exact
output was preserved before rerunning with socket permissions; the permitted
run passed all four. Logs remain in `/private/tmp/silo-native-perf/` as
`combined.*`, `combined-unsandboxed.*` and `updater.*`. Tauri resource inputs
were copied from the existing ignored test baseline. This verification used
fixtures, launched no application bundle and proves neither live VM health nor
package/release readiness.
