# Fresh animatic: review record

## Current disposition

**Do not extend this animatic into a finished film.** It is diagnostic evidence.
The useful finding is that one persistent remote VM and simultaneous local/remote
views can establish ownership. The current staging does not make that invariant
interesting enough: it is mainly a camera zoom into an editor, cursor work, then
a pullback. The hardware currently acts as a pedestal. Its enclosure does not
govern the action. The fictional preview is also more visually distinctive than
Silo. Encoding this successfully does not validate the direction.

## Two materially different next stagings

### A. The cutaway must actually contain the work

Keep a fixed three-quarter view. Begin with an opaque remote computer body, no
floating screen. Its lid moves backward and its front wall drops to reveal three
small separated VM cells that were inside it. The selected Silo row on the laptop
maps to exactly one cell; the other cells stay quiet. Its Start control changes
that cell from stopped to running. A flattened Linux work surface opens within
the cell boundaries, never above the box. Work changes that surface. The local
terminal/browser then opens as an access view while the still-running cell
remains plainly visible. A line rooted at the cell's port appears only when the
local connection becomes reachable.

**Product consequence:** this app gives an agent its own running computer and
lets the viewer access it from their laptop. Ownership is containment and local
access is a second view, not a traveling object.

**Motion mechanism:** enclosure opens, selected cell unfolds, local viewport
opens. Fixed camera; no nested zoom. The quiet other cells provide a visible
isolation boundary instead of an explanatory label.

**Risk:** too much literal architecture becomes an explainer diagram. Keep two
large states and one VM in detail; do not add a grid of decorative rooms. Do not
show runtime cells as literal hardware internals without the clearly diagrammatic
section-cut treatment.

### B. Two independent workspaces, one controlling screen

Discard the physical cutaway. Open tightly on a human-controlled terminal. A Silo
VM row interrupts its lower edge and opens like a shutter into a second desktop
alongside it. The human cursor keeps typing on the left. The blue agent cursor
maximizes a browser on the right, obscuring its own whole desktop, but its window
stops at the VM boundary. The human's workspace remains untouched. The agent
finishes a purposeful browser check and the result becomes reachable in a local
browser tab. Only then pull back once to reveal that the left workspace belongs
to the laptop, and the right one runs on the connected computer. The remote
workspace remains active while the local browser tab changes.

**Product consequence:** give the agent an entire computer to operate without
surrendering your own desktop, then inspect what it built using familiar tools.

**Motion mechanism:** the guest boundary is a hard physical shutter. An agent's
full-screen action presses against it and changes the composition while the
human action continues independently. The reveal resolves an apparent split
screen into two actual computers. It is a concurrency demonstration, not a
camera tour.

**Risk:** two tiny simultaneous stories will fail on a phone. Use one large
human action and one large agent action, no prose transcripts or code reading.
Do not imply that Silo supplies the agent executable or credentials.
